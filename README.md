### AIdvisor is an LLM-powered academic advising agent for Cornell students. It interviews a student about their major, interests, and background, retrieves real course roster, review, and program-requirement data through tool calls, and produces a cited, multi-semester course plan with the reasoning behind each choice.

For Cornell students, course planning is extremely challenging. Students are forced to navigate a somewhat archaic course roster page that makes it hard to ensure forbidden overlaps are avoided, prerequisites are met, and interests are met. For freshmen especially, developing a multi-year course plan that takes into account which semester classes are offered, which course path should be followed to develop the skills required for upper-level classes, all while picking up multiple minors (or potential other majors), is something that can take hours. An LLM is an extremely appropriate way to solve this problem: by acting as a personal advisor (AIdvisor), and supplied with information about each program, course roster, and course reviews, the AIdvisor can perform an advising session with the student to flesh out a course plan, across a multiple-semester horizon (depending on the student’s starting point). More specifically, when prompted with a student's area of study, interests/career paths, and prerequisite knowledge, the chatbot can "interview" the student to design potential assessments to test readiness for certain courses and optimize future semesters class selections (with respect to obtaining minors, for instance). The above task is best suited for chatbots that can engage in a personal level of conversation that another “pure optimization” model could not. 

LLM capabilities will be an essential part of the final product. At their core, several features depend on the LLM having the capability to make tool calls to APIs and scrape webpages. Any question that the student asks about information that can be found within the course roster, course review database, or Cornell’s program outline would require API calls to several endpoints. Additionally, since the LLM will work alongside students as their “personal academic advisor” and provide in-depth detail on a variety of courses, general skills to summarize information retrieved from the above calls is also a capability that is required from our LLM. The LLM should be able to not only answer scheduling questions but provide rationale behind every decision and explain to users why it believes it would be suited for them. If the student asks a question that is not part of the suite of capabilities, then the LLM will provide a helpful message explaining that it does not know the answer, alongside a link to academic advising meetings that could help answer the student’s question. That is, to prevent hallucinations, the information will always be cited from an approved source, and explicitly stated if not. 

The above features and required functionality necessitate agents that have the option to call tools and interpret their results. Generally, an AI agent’s reasoning path (for the aforementioned aspiring data scientist) might follow the structure of: (1) using the course roster API to get all INFO courses fitting the quantitative criteria, (2) appending information about course reviews from CU Reviews and program requirements (3), filtering down the qualitative requests, and finally (4) planning a schedule for the next four semesters based on the resulting information. Along the way, the model can ask the user clarifying questions, have it choose from a possible set of course options, or prompt the user to take a test to assess their prior knowledge of a fundamental course concept. The model we plan on using is Qwen3 8b (through Ollama), since its application for “role-playing, multi-turn dialogues, and instruction following” fits our needs well, along with native tool calling (Ollama). If we find this model is not complex enough to complete our task, we can replace it with a larger model.

By the final product deadline, the finished product will be an AIdvisor able to fully plan multiple semesters of personalized course selections, based on the current class rosters (which show patterns in course offerings), course reviews and major/minor program requirements (as outlined above), to act as a “personal academic advisor.” Additionally, the finished product will be able to ask the user questions about their interests, supply short “placement exams” to ensure students are starting at the correct level of expertise, and select courses for a student’s career plan. By combining multiple API calls and search queries into a single model framework, the final product goes beyond a single one-off feature. Furthermore, the final product is not something that a generic Claude or OpenAI model can do out-of-the-box since their responses are not grounded in an “oracle” of truth (Cornell’s websites) and having rigorous citations and deterministic checks for trust. Nor is it something that is immediately available to students (note the aforementioned several issues with courseplan.io and the course roster itself). Finally, the product is something that is genuinely useful for Cornell students and can be applied to other colleges as well, if they have suitable online infrastructure. Nonetheless, the final product is something readily achievable: the APIs we use are very well documented, and the program requirements are listed out plainly, only requiring minimal web-scraping for program requirements. If we find issues with feasibility, we can restrict our attention to A&S majors or subjects, though we don't imagine this being an issue. We also only focus on undergraduate programs and use a local model that is suited for tool calling. Each of these features directly builds on the topics discussed in class (namely, agentic modeling techniques for tool calls and chatbot interfaces).
